# Source Review: Error Recovery & Quality

Date: 2026-11-23

This document records a source-level review of `FastFileSearch` focused on
**error recovery** (how the code detects, reports, and recovers from failures)
and **code quality** (maintainability, safety, dead code, duplication).

Scope: all files under `src/` (~4,800 lines). No source files were modified by
this review.

## Summary

The dominant theme is that **raw-volume parsing trusts on-disk data and ignores
I/O short reads / failures**. Malformed or corrupted filesystem metadata can
cause undefined behavior, out-of-bounds reads, infinite loops, or hangs.
In the GUI, the worker thread has no cancellation mechanism and no exception
boundary.

Recommended priority:

1. GUI thread exception / cancellation boundary.
2. Bounds-check all binary-structure parsing and I/O short reads in the three readers.
3. Cycle detection in FAT/exFAT chain and directory traversal.
4. Unify error propagation so the CLI never reports false success.

## High severity — Error Recovery

| Location | Issue | Suggested fix |
|---|---|---|
| `src/MFTReader.cpp:143-161` | `DecodeDataRuns` shifts `uint64_t` by up to 112 bits and computes `1LL << 119` — undefined behavior on corrupt runs. Negative LCN deltas wrap to huge values (`:163-164`). | Reject `lenBytes/offBytes > 8`; clamp all shift counts; treat negative `currentLcn` as corruption. |
| `src/MFTReader.cpp:203-223` | Disk-supplied `AttributeOffset` / `RealSize` used as pointers with no bounds check before casting → out-of-bounds reads on a corrupt record. | Validate all offsets/sizes against `recordSize` before casting `buffer.data()`. |
| `src/MFTReader.cpp:284`, `src/FatReader.cpp:276` | `SetFilePointerEx` return value ignored; a failed seek causes reads from the wrong location. | Check the return; call `SetError` and abort on failure. |
| `src/MFTReader.cpp:289-305` | `ReadFile` checks only the boolean result, not `bytesRead == toRead`; short reads accepted, bad-sector failures abort the whole scan with no retry. | Loop to fill the request, retry on `ERROR_CRC` / `ERROR_IO_DEVICE`, report short reads via `SetError`. |
| `src/FatReader.cpp:265-368`, `src/exFatReader.cpp:109-192` | No cycle detection in cluster chains or recursive directory traversal → infinite loop / stack overflow on a corrupt FAT. | Keep a visited-cluster set and a recursion-depth cap; treat a revisit as end-of-chain. |
| `src/FatReader.cpp:57-81` (esp. `:69`), `src/exFatReader.cpp:60-65` | BPB values used unvalidated: divide-by-zero on `bytesPerSector == 0`; UB shifts on unvalidated shift counts; FAT32 `rootCluster` unchecked. | Validate geometry (power-of-two ranges, `fatCount > 0`, `cluster >= 2`) in `Initialize` before arithmetic. |
| `src/FatReader.cpp:226-230`, `:337-341` | `MultiByteToWideChar` length result unchecked → `new wchar_t[0]` then `std::wstring` reads uninitialized/OOB memory; raw `new[]` leaks if assignment throws. | Require `len > 0`; use `std::vector<wchar_t>`. |
| `src/main.cpp:1170-1174`, `:292-385` | `_beginthread` handle discarded, no cancel flag or join; `EndDialog` can run mid-scan. `ScanThread` has no `try/catch` — a throwing reader terminates the process and leaves `isSearching == true` forever with no message posted. | Keep the handle, add a cancellation flag checked in scan loops, wrap the body in `try/catch` posting `WM_USER+2` with the error text, join/wait on dialog close. |
| `src/main.cpp:36-43`, `:299-350` | Data races: worker mutates `searchResults` while UI reads it in `PopulateList` / `CompareFunc` / `SaveResults`; `searchTargets` / `g_options` / `currentCodePage` read and written from both threads. | Pass an immutable snapshot to the worker; marshal results back via `PostMessage`; confine shared state to the UI thread. |
| `src/main.cpp:296` | Worker calls `GetDlgItemTextW` (cross-thread `WM_GETTEXT`) — deadlock if the UI thread waits on the worker. | Read the query on the UI thread and pass it in the thread parameter. |
| `src/main.cpp:1272-1282` | `GlobalAlloc` / `GlobalLock` returns unchecked (NULL deref); `SetClipboardData` + `CloseClipboard` executed twice with the same `hMem` after ownership transferred to the system. | Check allocations; call `SetClipboardData` exactly once. |
| `src/main.cpp:1300` | A localized string is used as the `wsprintfW` **format string** with a `size_t` argument — a translation containing `%n` or wrong specifiers causes UB/crash. | Use a fixed format literal with validated specifiers; append the count separately. |
| `src/cli_main.cpp:96,114` | All readers compile the regex per item inside `try/catch(...)` and silently treat syntax errors as "no match". A malformed pattern like `ffs "["` prints nothing and exits 0. | Compile the regex once in `wmain`, catch `std::regex_error`, print the pattern and error, return 1. |
| `src/test_console.cpp:133-135` | `GetVolumeInformationW` return ignored and `fsName` uninitialized; on failure it is printed and passed to `wcscmp` (`:178,195,213`) — undefined behavior. | Initialize the buffer, check the return, print `GetLastError()`, return 1. |
| `src/test_console.cpp:59-74` | `swscanf` return values and `SystemTimeToFileTime` success unchecked; `--min-date abc` leaves `st` zeroed and `ft` uninitialized → garbage date filter. | Require 3 parsed fields, validate ranges, check `SystemTimeToFileTime`, abort with an error otherwise. |

## High severity — Quality

- `src/MFTReader.cpp:22-30` — uninitialized `LPVOID lpMsgBuf` and ignored `FormatMessageW`
  return; on failure the ternary reads an indeterminate pointer. Initialize to
  `nullptr` and only use it when formatting succeeds.
- `src/MFTReader.cpp:91-111`, `:269`, `:307` — `1 << (-val)` uses `int` with `-val` up
  to 128 (UB); `recordSize` / `bytesPerCluster` never validated as nonzero → divide
  by zero. Validate ranges with `uint64_t` shifts and reject zero values.
- `src/MFTReader.cpp:381-415` — `RESIDENT_ATTRIBUTE_HEADER` fields read after only
  `sizeof(ATTRIBUTE_HEADER)` bytes are guaranteed → overrun on a truncated attribute.
  Require the full header size before casting.
- `src/main.cpp:320-344`, `:1307` — every failure is reported as
  `mftReader.GetLastErrorMessage()` even when `GetVolumeInformationW` or the
  FAT/exFAT scan failed; no "run as administrator" hint for denied raw-volume
  access. Track per-drive error and inspect `GetLastError()` for
  `ERROR_ACCESS_DENIED`.

## Medium severity

- **Error propagation** — `Scan` always returns `true` in `FatReader.cpp:144-254` and
  `exFatReader.cpp:88-98`; read failures only `break` without `SetError`. MFT failure
  paths at `:198-199` and `:256-257` return `false` with a stale/empty message.
  Return a status from `ProcessDirectory` and propagate it.
- **Corrupt metadata** — LFN fragments concatenated without sequence/checksum/type
  validation (`FatReader.cpp:185-193`); LFN run never cleared at a deleted/volume-ID
  entry; exFAT ignores `NameLength`, copies 15 `wchar_t` leaving `0xFFFF` padding, and
  never verifies `SetChecksum` (`exFatReader.cpp:151-154`); `SystemTimeToFileTime`
  return ignored with unvalidated fields (`:195-216`); `cluster - 2` underflows for
  clusters `< 2` (`FatReader.cpp:140-142`, `exFatReader.cpp:84-86`).
- **Read failures** — `SetFilePointerEx` / `ReadFile` returns and `bytesRead` ignored in
  `FatReader.cpp:89-103`, `:278-283` and `exFatReader.cpp:70-82`, `:115-117`; a short
  FAT read leaves a zero-filled cache, a short directory read reuses stale buffer
  contents. Require full reads and zero the buffer each iteration.
- **Input validation** — corrupt ini values unvalidated: `Count` drives an unbounded
  loop and enum/code-page/size values are cast directly (`main.cpp:613-634`, `:667-679`);
  CLI target folder never normalized/validated (`cli_main.cpp:57-72`); unknown CLI
  flags (`-`/`--`) silently become regex patterns and `argv[3+]` is dropped
  (`cli_main.cpp:41-58`); empty target not checked (`ffs "pat" ""`).
- **Resource / API handling** — `LoadMenu` / `GetSubMenu` unchecked and menu never
  destroyed on every right-click (`main.cpp:1262-1267`); `CreateDirectoryW` and
  `WritePrivateProfileStringW` returns ignored so settings can be silently lost
  (`main.cpp:503-587`); `OFN_FILEMUSTEXIST` on the Save dialog prevents new filenames
  and `std::wofstream` failures unchecked (`main.cpp:442`, `:446-452`);
  `FileTimeToSystemTime` / `SystemTimeToTzSpecificLocalTime` returns ignored
  (`main.cpp:108-109`); `InitCommonControlsEx` / `CoInitialize` results ignored
  (`main.cpp:1328-1330`); `CB_GETITEMDATA` can return `CB_ERR` → `currentCodePage == -1`
  (`main.cpp:1182-1185`).
- **Duplication** — `FatReader` and `exFatReader` duplicate ~180 lines of matching,
  filtering, path building, and handle lifetime that have diverged (`LastWriteTime = 0`
  at `FatReader.cpp:557` vs. real value at `exFatReader.cpp:409`; `exFatReader::Scan`
  ignores all callbacks). Extract a shared base/helper.
- **FAT12** — misdetected as FAT16 (`FatReader.cpp:63` only checks `SectorsPerFat != 0`)
  and `LoadFat` always reads 16-bit entries → broken chains on FAT12 volumes.
- **Cluster loss** — exFAT entry sets crossing a cluster boundary are silently skipped,
  and the `>=` bound also skips a set ending exactly at cluster end
  (`exFatReader.cpp:123-137`).
- **ID collision** — synthetic IDs `0x80000000 + …` collide with legitimate FAT32/exFAT
  clusters (`>= 0x80000000`) and use inconsistent formulas (`+i` vs. `+fileMap.size()`),
  silently overwriting entries (`FatReader.cpp:237-241`, `:348-352`, `exFatReader.cpp:166-170`).
- **Locale assumptions** — LFN decoding `memcpy`s raw bytes into `wchar_t[]`, assuming
  `sizeof(wchar_t) == 2` and packed-struct layout (`FatReader.cpp:187-191`,
  `:294-297`). Decode UTF-16LE explicitly with `static_assert(sizeof(wchar_t) == 2)`.

## Low severity / maintainability

- `src/MFTReader.cpp:198-199`, `:256-257` — `Scan` returns `false` for bad magic or
  empty runs without calling `SetError`; callers get a stale message.
- `src/MFTReader.cpp:334` — `(processedRecords * 100) / totalRecords` divides by zero
  when `totalRecords == 0` and can overflow before the cast to `int`.
- `src/MFTReader.h:81-92` / `MFTReader.cpp:169-335` — mutable shared state (`hVolume`,
  `fileMap`, `lastError`, callbacks) has no synchronization and there is no
  cancellation: `progressCallback` returns `void`. Document single-threaded use or add
  a mutex plus an atomic cancellation flag checked in the read loops.
- `src/MFTReader.cpp:334` — `scanDebugCallback` cleared only on success; early returns
  leave a stale callback. Use a scope guard / clear before every return.
- Dead / unused code: `MFTReader::ProcessBuffer` declared but never defined
  (`MFTReader.h`); `startVcn`, `lastVcn`, `totalClusters`, `clustersPerRecord`,
  `parentPath`, `traceCallback`, `onFileFound`, `totalSectors` unused; `PerformSearch`
  never called (`test_console.cpp:140-162`); `temp_logic.cpp` / `temp_draw.cpp` duplicate
  stale implementations with wrong field names and break the build if added.
- God object / huge functions: `DialogProc` (~334 lines), `ConfigDlgProc` (~205),
  `UpdateLanguage` mixes translation with layout measurement (`main.cpp`). Pervasive
  mutable globals with no ownership model; encapsulate in an `AppState` object.
- Magic numbers throughout (`WM_USER+1/2/3`, `50000` result cap, layout constants,
  `1MB`, filesystem signatures `0x454C4946` etc.); replace with named constants.
- Startup-guard subclassing plus "purge mouse messages" timer hack can swallow legitimate
  input, never restores the original `WNDPROC`, and uses a magic timer ID/interval
  (`main.cpp:56-80`, `:1014-1029`, `:1124-1154`).
- Casting away `const` on `c_str()` into writable Win32 buffers is UB if the callee
  writes (`main.cpp:404`, `:408`, `:411`, `:414`).
- Localization: `g_Strings` rows use positional aggregate initialization with unchecked
  `GetString` results passed directly to `SetWindowTextW` and `wsprintfW`
  (`Localization.cpp:6-204`, `:224-228`); an out-of-range ID silently returns `L""`
  (`:225-226`); 6 of 8 languages have only 15 of 48 strings translated. Tables are
  mutable globals with external linkage and `<vector>` is unused.
- CLI diagnostics print errors to `std::wcout`, so piping stdout hides them
  (`test_console.cpp:148`, `:185`, `:190`, `:202`, `:208`, `:220`, `:225`, `:230`);
  stale "Added for..." / design-deliberation comments; unqualified `min` relying on
  a Windows macro; hardcoded `L"D:"`, `L"ws"`, result limit 100.
